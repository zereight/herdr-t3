# Herdr T3

A calm, T3 Code-like window for Herdr App that saves your attention as agents multiply. It opens on an Inbox with T3-style Settle: agents that need you stay up top as cards, busy ones fold into a Working shelf, and finished ones wait until you settle them, coming back on new work. One key switches to Lists (Spaces + Agents), and agents on your other machines sit in the same sidebar, marked by machine. Slim tabs and framed panes use the same names and status marks. Actions, as T3's run button, keeps your commands at the tab bar: `▶` runs the last one again, in a new tab or a split. An optional Review bar, for pulls.review, counts what there is to review in the focused worktree and opens it in a pane beside the agent.

## How it behaves

- **Terminal addresses**: a pane's right-click menu, on its header or its terminal, has `Copy address` with the address where a key would show (`t2`), so you can tell an agent which terminal even when programs retitle them; a mod pane has none. Headers don't show it. The sidebar leaves it out: there the name needs the room.
- **Go to** (`t3-picker`, a `mod.clone` of the shipped `picker`; `cmd-p`, and Inbox's Search through its `picker` prop), drawn as the New menu, as T3's command palette: a popup 96 from the top, 576 wide, as tall as what it shows up to 420, `frame: "none"` with the same radius 16 shell, no fade, a borderless 36px search field with 6px above and below, then the list with no heading (one kind of row), 48px two-line rows that scroll with the highlight past 313px, six and a half of them, and a footer with key hints (`↑ ↓` Navigate, `Enter` Go, `⌃D` Close pane, `Esc` Close) and, at the right, New tab (opens `t3-new-menu`). A row a pane, not a tab: every pane, agents, programs, shells and mod panes, the current space's first, then its machine's, as New orders spaces, each in tab order. A row: the space's mark (16px), the name by the naming rule, as its pane header, and under it the program icon and name (`panes()`'s `program` follows what runs in front: lazygit started from a shell is `lazygit`), a server icon and machine when remote, the space, and live sub-agents as `+n`; at the right the status mark, by the same rule and marks as the pane headers (a settled or snoozed agent shows no done dot, in Inbox and Lists alike). A tab's name is no row: unnamed it is its position ("4") or what it was first, not what runs in it. Typing matches a pane by its space and machine, its tab's name only if someone named it, its name, its program's name and key and its folder; the highlight goes to the first match. Enter or a click is `pane.focus` (across spaces); ctrl+d closes the pane through `t3-tabs.close-pane:<pane>`, which asks first while a program runs. The pane a jump from here leaves is kept in `shared("t3-picker.back")`; while that pane is there and not focused, the first row goes to it (`↩ Back` at its right) and an empty query opens on it, so `cmd-p`, Enter goes back and forth; else it opens on the focused pane. Only jumps from here count: a click elsewhere isn't seen. No rows for terminals without a pane.
- **Space marks**, as T3 Code draws a project (`ProjectFavicon`), in `shared/project.js` with a copy in t3-inbox, t3-agents, t3-picker, t3-spaces, t3-new-menu, t3-tabs and t3-menu: the project's own icon (16px on Inbox cards, in Spaces and in New, radius 25%), looked for as T3 does from the repo top of where the space is now (its first terminal's folder, else where it was made): T3's well-known files in order (`favicon.svg`, `public/favicon.ico`, … `.idea/icon.svg`; no `.icns`), then a page's `<link rel="icon">` or a route's `{ rel: "icon", href }`. Found, it is copied to `cache/t3-icons/` (images show only from the app's folder; named by content) and shared as `space.icons`; looked for again after 10 minutes, a missing one after a minute. Else a monogram: unlike T3's two letters, the name's first letter or digit, capitalized (`herdr-t3` → `H`, `智能算量` → `智`), in bold monospace at 8.25/16 of the mark, as T3's, in one of T3's 18 colors hashed from the name (Tailwind 400 on dark, 600 on light) on a 14% wash of it. A name with nothing to spell (`~`) shows a folder. `space.colors` gets the same colors (600) for the shipped picker.
- **Names**, one rule everywhere (inbox cards, agents list, tabs, pane headers), in `shared/name.js` with a copy in each mod that uses it: the Pi session (`pi.session` label) while Pi runs, then for an agent a tab someone named, unless it is a sub-agent or another top-level agent shares the tab (they would read alike; Herdr's agents list stopped doing that too), then a telling terminal title (not one in an agent's marks on a terminal that runs no agent: that is a title left behind, as lazygit's after Pi; each agent's own marks taken off its own titles only: Pi's `π - … - <folder>`, OpenCode's `OC | `; not a path, not `user@host`, not the program's own name, not just the folder or space name, as Codex and an unnamed Pi set), else the program's name. omp's own marks (`π`, its state glyph and the session's icon) come off its titles like Pi's. A session name or title that isn't Korean is shown in Korean from `shared("t3-korean.names")` (title -> Korean, at most 300, the oldest dropped), which the tab strip's `t3-tabs` fills (`korean.js`, its main copy only): the titles in view that aren't Korean yet go, 8 a call, to `claude -p` (Haiku, the person's own login, no tools, no session saved, none of their hooks), and one that fails is asked again after 5 minutes; until an answer comes, or with no `claude`, the title shows as it came. A tab someone named and a title already in Korean are left as they are.
- **Agent statuses**, the same marks everywhere (agents list, tabs, pane headers, inbox cards): working: spinner in `working`; blocked: a 14px rounded `!` badge on `blocked` at 15% opacity (16px on an Inbox card, 12px in the agents list, as T3's one-line row); done: a 6px `done` dot (Inbox: green `Done`); idle: a ring in the agents list, nothing elsewhere. A parent reads with its live sub-agents, one rule in `shared/tree.js` with a copy in each mod that uses it: blocked if it or any sub-agent is (a failed turn, the terminal's `error`, counts as blocked: `agents()` has no such word, so it is read from `terminals()`), else its own unread done, else working if it or any sub-agent is, else its own state; a sub-agent's done is its parent's news, not its own. A sub-agent is a live terminal under it that is an agent, as `agents()` has them: it reports a status, or the program table marks it one; a shell an agent ran a command in (`hc run --bg`) isn't, though an agent that shell started is. The pane header's count and list, the agents list's sub-agent rows and fold count, and Go to's `+n` go by this.
- **What a hidden copy can't do**: a mod in a hidden stack child or column doesn't draw and hears no `<mod>.<command>`, though its timers run, and it doesn't start until it first shows. So Inbox and the agents list work out their rows in a method a 1s timer also runs, not in `render()`, and only the mode selected writes `setAgentOrder`: the selected mode holds with the sidebar hidden. A rule others rely on isn't only Inbox's to apply: whoever reads a `settled` label goes by `stillSettled` in `tree.js` (busy now, or a turn ended since, means it no longer is), and times come from the tab's `changed_at`, not from when a list last drew. Keys that must always work go to `t3-tabs`, which always shows, and so does ending a snooze on a failure in its tree or a new turn given in view.
- **Sidebar mode**: the brand bar button or `cmd-shift-b` (`t3-tabs.sidebar`, the copy that always shows, so the key works with the sidebar hidden, which it leaves hidden) runs `layout.select` on stack `sidebar-lists` (`lists` / `inbox`). The two modes share the facts (names, pins, what the `settled` and `snoozed` labels mean); the Inbox's ways with attention (Settle, landing on Home, Snooze hiding work, its space filter) hold only while it's the mode: see `docs/adr/0002-inbox-rules-stay-in-inbox.md`. The sidebar toggle counts as the selected mode shows: a settled or snoozed agent's done dot is left out in both; with the Inbox, a snoozed one that's working leaves the counts too, until it wakes or needs you.
- **Actions**: the [t3-actions](https://github.com/JinJieBeWater/herdr-t3-actions) mod, described in its own recipe. As T3 Code's project actions but global: the primary action is the one run last, else the first. `▶` runs it; a menu row runs that action and makes it primary; the gear opens the editor, T3's dialog: 512 wide and as tall as its fields, `frame: "none"` with its own radius 16 shell, 24px padding, a 20px semibold title, a 32px close 8 in from the corner, 32px fields and buttons of radius 8. Running is `terminal.open { argv: ["sh", "-c", command], name, place, folder? }`: a new tab or a split right/down every time, named after the action; the shell stays when the command ends. With no folder it starts in the focused terminal's folder; with a mod pane focused (a review beside its agent), a terminal's in the same tab, else the space's; `~` is expanded. Actions live in `shared("t3-actions")` = `{ list: [{ id, name, command, icon, place, cwd? }], last }`, which Herdr keeps across restarts.
- **Worktrees**, grouped by repo as T3's projects, so closing a checkout doesn't scatter them: under the checkout's row, or, with it not open and two or more of them, under a dim row standing for it, where the first worktree was (one alone stays a plain row, with `repo · branch`). It has a checkout's fold arrow but no tab to go to, so its click opens the checkout with `space.new`, once however often it's pressed (a bare repo has nothing to open: there the click folds). The checkout takes the dim row's place, so the group stays where it was. It isn't a space, so `space.next` / `space.prev` and `ctrl-1…` pass over it. The fold is kept by repo, either way. Keep the node ids `sidebar`, `sidebar-lists`, `lists`, `inbox`.
- What shows on hover goes with the pointer even when its leave never comes (`pointerGone` in `tip.js`). Herdr drops a leave while the pointer's last known place is in the element's last box, and GPUI has by then marked it left: a key press then a first move out of the row, a press dragged out and released, or the pointer leaving the window strand a hover. So a label or a row's card, while up, checks `mouse_position()` against its element's box every 100ms, and so does what a hover lights with neither (`hoverKept`: an Agents group's chevron, a Review group's category icon). Hovering works the same in a window that isn't active, as in T3. macOS sends a window, active or not, no moves once the pointer is out, so a pointer that hasn't moved since a last step that, taken twice more, crosses the window's edge has left it. A drag also ends when the window goes inactive, as its release may never be seen.
- Hover labels are `shared/tip.js` (a `Popup` drawn as T3 Code's tooltip, with its own timing as a `HoverCard` stays open under the pointer and a popup blocks what it covers even when clear. It fades and slides 4px off its control over 150ms, in once laid out and out again, with a new id each opening since a size reports only an id's first layout: 12px, 320px at most, the label with its bound key from `keys()` when that key does what the control does, an optional dim hint), copied to each mod that uses it. As in T3 a label names its control in a few words, whether or not the control has words of its own; a second line is only for what can't be seen (Shift+click). Icon-only buttons and status marks have one; a program's icon, the pin and a machine's mark don't. The machine's name is in the row's hover details. They open above, as T3's; what has no room up there (the brand bar, the tab bar with Actions and the Review bar, the Actions menu's rows, the filter's two lines) passes `below`: a `Popup` doesn't flip as T3's does. `.tooltip()` takes only a string in the shell's own style.
- Controls inside a row are one of three, by whether clicking them differs from clicking the row. A button does something the row doesn't (a machine's `+`, the worktree and sub-agent folds, the pin, an Inbox card's clock, Settle and undo or Wake, a tab's `×`): dim until hovered, with a hover label, and sized as T3's: a machine's `+` 24px, radius 8, a 14px icon, as T3's folder button (`icon-xs`); a worktree or sub-agent fold 20px tall, radius 4, a 12px chevron; the pin 24px, radius 6, a 12px icon; the clock 20px tall, radius 6, a 12px icon; Settle 20px tall, radius 6, a 14px icon; undo or Wake 24px tall, radius 6, a 14px or 12px icon; a tab's `×` 16px, radius 4, a 12px icon, in its 24px tab's slot. As T3's: in a sidebar row or card it only lights up to `foreground`, no ground (`bg-transparent`, `hover:text-foreground`); a tab's `×` takes a `raised` ground, as T3's tab close does `bg-muted`. An indicator is the row's own (the chevron of a group header, a machine's, an agents group's or an Inbox shelf's: its row folds): no ground and no label, lit while the row is hovered. A mark only says (a status dot, `↑2`): a label, no ground. Bars and headings use radius 8 buttons with a `hover` ground, as T3's ghost and header buttons: 28px with 16px icons in the Spaces and Agents headings and Inbox's top row, 28px with 16px icons in the brand bar, 24px with 14px icons for the tab bar's `+` and in a pane header.
- Program logos use `shared/program.js`'s `programIcon` everywhere: Inbox, Agents and their details, tabs, pane headers, Go to and sub-agent rows. Each component keeps its T3 icon slot (12, 14 or 16px). Draw the artwork supplied by Herdr or the mod as it is, preserving its canvas, tinting, colors and aspect ratio.
- Icons are Lucide's (24 grid), as T3 Code's and shadcn/ui's; drawn with 1.75px strokes, as T3's CSS thins Lucide's 2px, so each mod keeps its own copies in `icons/`, the shipped `workspace-chrome` ones too (`x`, `git-branch`, `panel-left`, …, at 2px there); only the shipped spinner, not Lucide's, is used as it is. Besides those: the pane header's splits and zoom in `t3-pane`, and the Review extra's in `review/icons/` (its category icons included: the app's are Phosphor duotone) and `pulls-review`. Not Lucide: programs' icons (their marks), Review's file icons (catppuccin), the Windows window buttons, the spinner.
- Git that touches the index wakes the folder watch again: always pass `--no-optional-locks -c core.fsmonitor=false`.
- A settled label takes about 0.65s to show in `terminals()`: keep a pending value. On a slow remote, writes to one label can land in any order: while more than one is out, keep the last intent and, once all have answered, write it again if the label says otherwise.
- On macOS with no title bar, the tabs leave room for the window buttons when the sidebar is hidden or narrow (`layout().traffic_lights`).
- Narrow windows: `bar-measure` (`t3-tabs` with `part: "measure"`), in `work-bottom-inset`, sets `shared("bar.compact")` while the work column is under 1024 logical px (past T3's 768: here the controls share the row with the tabs); Actions and the Review bar then drop their text. It measures there because the strip's width doesn't depend on the bar: measuring the tabs would undo itself as the controls fold.
- Actions run through `sh -c`: your shell's aliases and functions aren't there (write `zsh -ic '…'` in the command for them), and plain Windows has no `sh`.
- A review picked from the Review bar's logo menu loads as one from a count does: the review pane starts its first read on its own 0ms timer (`cx.timer.after(0, …)` in `init`). The pane is made as the menu closes, and a read started in `init` itself then never answers and times out after 30s.
- `t3-actions` and the bar's end (`t3-tabs` with `part: "end"`) size their own blocks: `run("layout.resize", { id: props().block, px })`, the width from `on_size_change` divided by `settings().zoom` (it reports zoomed pixels). `tabs-row` stays unresizable, or a drag would fight them. A layout naming a mod that isn't installed reports `no mod folder` in `herdr-app status`: copy every `mods/t3-*`, `t3-actions` included.
- The tab strip keeps the active tab in view with the least move, as T3's `scrollIntoView({ inline: "nearest" })`. Herdr's scroll areas can't be moved from a script, so `tab-scroll` clips and `tab-strip` is offset with `.ml()`; a tab's whole width comes from a zero-height copy of its name, measured with `on_size_change`. It moves only when the active tab or the room changes, so a sideways swipe isn't pulled back; the wheel still walks the tabs.
- The `check*.cjs` beside a mod load it in a fake `herdr`. `scripts/check.sh` runs them all from an installed home, where some look for the shipped icons, with `herdr-app check` on each mod and a comparison of the shared modules' copies. Each mod is also type-checked (`tsc --noEmit`) with the options written in `check.sh`, not with the mod's `jsconfig.json`: that file is ignored by git, and the default one `herdr-app check` writes fails these mods.

- Home is known by the id in `shared("t3-home.space")`, never by what's in it: someone may have closed the default page. That id is this computer's while the space is the core's, so its name is `Home` plus a zero-width space (`\u200b`), which reads as Home everywhere and nobody types: `t3-tabs` takes a named space on this machine with exactly that name as Home when it knows none, and gives an existing Home that name. A space merely called Home is never taken: being wrong would hide it, and missing costs at most a second Home. `t3-tabs`' strip copy answers its commands, as the tab bar always shows and the brand bar goes with the sidebar. `spaces()` catches up a frame or so after a command, so creating it waits to see each step. A space opens with a shell and can't lose its last tab, so the page goes in before the shell leaves. It keeps its place in the model's order, which `t3-spaces` keeps with the rows', so `ordered()` drops it only from the rows it returns.

- `scripts/check.sh` prints `all checks passed`.
- `cmd-shift-b` switches the sidebar between Lists and Inbox.
- In Inbox, `cmd-shift-s` on a finished agent in view settles it and lands on Home, with no tab, `+` or Actions in the bar; Undo there brings it back to its old place in Active and clears the label; `cmd-]` there opens the top card; `ctrl-1` still shows the first project.

- In Lists, `cmd-shift-s` does nothing; a snoozed agent's row still spins while it works, and a done one shows no dot.
